## How claims are marked

The dossiers do not present every sentence as equally certain. Respect the markers when you
quote from them, and carry the marker forward into any deliverable.

- **`[verified]`** — the page was fetched and read.
- **`[search-level]`** — taken from a search-result summary only. Re-check before stating it as
  fact in client-facing work.
- **`[illustrative]`** — an invented number used to make arithmetic followable. Never publish it.
  Replace it with a measured figure.
- **`[UNVERIFIED - ...]`** — a named gap, with what is missing and what would close it.
- Inline `(source: URL, retrieved YYYY-MM-DD)` for external facts. Physics, optics and
  arithmetic carry no citation; the derivation is shown instead so it can be re-checked by hand.

Retrieval date for external facts across these files: 2026-07-29. Anything time-sensitive,
priced, versioned, or platform-specific needs re-checking against the live source before use.

## Known limits

**Two files are partial.** `food-and-beverage-imagery.md` stops at section 5 and
`layout-wireframe-typography.md` at section 5, because those research runs hit an output limit.
What is there is finished prose, not notes. The table above says where each one stops, and the food
file forward-references sections that do not exist. Do not assume a topic is covered because the
filename suggests it — check the headings.

**Three topics have no dossier at all**: campaign and channel architecture, optics and lens, and
brand identity systems. The concise references in `../` cover these at working depth; the deep
evidence audit does not exist. Do not cite a dossier for them.

**No adversarial verification pass has run** over any file here. Each dossier carries its own
per-claim markers, and that is the only guard until one does. Treat an unmarked claim in these
files as unverified rather than as verified-by-omission.
